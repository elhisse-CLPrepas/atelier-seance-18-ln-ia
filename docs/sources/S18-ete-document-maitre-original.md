# SÉANCE 18 — MANIPULER : PRODUIRE LE MINI-SITE V1

**Module :** 05 — De la page web simple à la mini-application statique déployable  
**Semaine :** 09  
**Version :** V2  
**Statut :** VALIDÉ  
**Date de validation humaine :** 27 juillet 2026  
**Durée indicative :** 110 minutes  
**Pilotage humain :** Prof. Abderrahman El Hisse

> La séance 18 organise la production guidée d’un mini-site V1. Le guide interactif V2 de suivi est validé et publié sur GitHub Pages.

## 1. Type de séance

Atelier pratique guidé avec manipulation individuelle, contrôles intermédiaires et preuve de production.

## 2. Intention

Transformer un contenu métier vérifié en un premier mini-site structuré, lisible, responsive et comprenant une interaction JavaScript simple, tout en conservant la maîtrise humaine du contenu et des corrections.

## 3. Résultat essentiel attendu

Le candidat produit un mini-site V1 local, explique le rôle de ses fichiers, exécute les contrôles essentiels et conserve une preuve datée de sa production.

## 4. Objectifs observables

- confirmer le sujet, le public, l’objectif et l’appel à l’action ;
- créer une arborescence simple avec des chemins relatifs ;
- structurer une page HTML sémantique ;
- appliquer une identité visuelle CSS lisible et responsive ;
- ajouter une interaction JavaScript simple et explicable ;
- tester l’affichage sur ordinateur et téléphone ;
- contrôler la console, les liens et la navigation clavier ;
- documenter la production dans un README et une preuve.

## 5. Compétences visées

- cadrage d’un besoin web simple ;
- classement des fichiers ;
- adaptation fidèle du contenu métier ;
- hiérarchie visuelle ;
- interaction locale ;
- test, correction et documentation de premier niveau ;
- usage contrôlé de prompts de production.

## 6. Prérequis

- acquis et cadrage de la séance 17 disponibles ;
- sujet, public, objectif et appel à l’action confirmés ;
- textes et visuels autorisés ;
- interaction simple choisie ;
- environnement de travail et navigateur opérationnels.

## 7. Matériel à prévoir

- poste de travail ;
- navigateur moderne ;
- éditeur déjà disponible ;
- fiche projet issue de la séance 17 ;
- ressources locales autorisées ;
- guide interactif V2 de suivi ;
- dossier de production du candidat.

## 8. Message d’ouverture

Produire une première version simple, compréhensible et testable avant de chercher à la perfectionner. Chaque ajout doit servir l’objectif du projet et rester contrôlable par le candidat.

## 9. Vocabulaire essentiel

Arborescence, HTML sémantique, sélecteur, classe, responsive, événement, fonction, état, chemin relatif, console, README et preuve.

## 10. Déroulement chronométré

| Phase | Durée | Intention | Activité |
|---|---:|---|---|
| Cadrage et fiche d’entrée | 10 min | confirmer les données du projet | compléter la fiche et exclure les données sensibles |
| Structure HTML | 20 min | organiser le contenu | créer les sections sémantiques et vérifier la hiérarchie |
| Mise en forme CSS | 20 min | rendre la page lisible | appliquer couleurs, espacements et responsive |
| Interaction JavaScript | 15 min | ajouter une action utile | intégrer et expliquer une interaction simple |
| Contrôles intermédiaires | 20 min | repérer les anomalies | tester chemins, affichage, clavier, mobile et console |
| Corrections autorisées | 15 min | améliorer sans dériver | corriger uniquement les écarts confirmés |
| README et preuve | 10 min | documenter le résultat | compléter la documentation et la preuve 18 |

**Total : 110 minutes.**

## 11. Démonstration du formateur

À partir d’un contenu fictif ou autorisé, présenter l’arborescence, relier chaque contenu à une balise HTML, montrer la séparation HTML/CSS/JavaScript, expliquer une interaction simple, provoquer puis corriger un chemin erroné, contrôler le responsive et la console, puis distinguer production, contrôle et validation humaine.

## 12. Exercice guidé

Construire collectivement une section comprenant un titre clair, un contenu fidèle, un appel à l’action, une classe CSS et un contrôle de lisibilité sur écran étroit. Le groupe explique le rôle de chaque élément avant de poursuivre.

## 13. Manipulation du candidat

Le candidat adapte l’arborescence, intègre uniquement les contenus autorisés, applique une identité visuelle sobre, ajoute une interaction simple, teste chaque étape, note les anomalies, autorise les corrections puis complète son README et sa preuve.

## 14. Exemple commenté

Le mini-site de démonstration de la séance 17 sert de référence. Il doit être observé et expliqué, jamais copié sans adaptation au projet du candidat.

## 15. Prompt de production

Le parcours opérationnel est assuré par les prompts 18-A à 18-F intégrés au guide interactif V2 :

- 18-A : cadrage ;
- 18-B : structure HTML ;
- 18-C : mise en forme CSS ;
- 18-D : interaction JavaScript ;
- 18-E : audit sans modification initiale ;
- 18-F : README et preuve.

Chaque prompt se termine par un rapport et conserve le statut du livrable candidat à valider.

## 16. Erreurs fréquentes à traiter

- contenu inventé ou promesse non validée ;
- fichiers mal classés ou chemins absolus ;
- texte peu lisible ou interaction non expliquée ;
- absence de test mobile ;
- correction automatique non autorisée ;
- donnée personnelle ou secret dans le projet ;
- confusion entre guide publié et livrable candidat validé.

## 17. Procédure de test

- vérifier les fichiers attendus et ouvrir la page sans erreur critique ;
- contrôler titres, textes, images et chemins relatifs ;
- tester l’interaction plusieurs fois ;
- vérifier l’affichage sur ordinateur et écran étroit ;
- parcourir la page au clavier et observer la console ;
- vérifier l’absence de données sensibles ;
- relire le README et la preuve ;
- consigner les résultats réussis, échoués ou non testés.

## 18. Critères de contrôle

- contenu fidèle au projet ;
- structure compréhensible ;
- page lisible et responsive ;
- interaction fonctionnelle et explicable ;
- chemins relatifs et aucune donnée sensible ;
- erreurs critiques traitées ou signalées ;
- README et preuve datée présents ;
- validation finale laissée au pilote humain.

# SUPPORT FORMATEUR — SÉANCE 18

**Version :** V1  
**Statut :** À VALIDER  
**Type :** atelier pratique guidé

## Intention

Transformer un contenu métier vérifié en mini-site V1 local, simple, responsive et explicable par le candidat.

## Résultat essentiel

À la fin de la séance, le candidat possède un dossier organisé et peut montrer :

- où se trouve la structure HTML ;
- où se trouve la présentation CSS ;
- où se trouve l’interaction JavaScript ;
- comment ouvrir et tester la page ;
- quelles corrections ont été réalisées ;
- pourquoi le projet n’est pas encore publié.

## Prérequis candidat

```text
[ ] preuve 17 complétée
[ ] titre du projet confirmé
[ ] public identifié
[ ] besoin du public formulé
[ ] message central vérifié
[ ] trois contenus ou bénéfices disponibles
[ ] action principale choisie
[ ] interaction simple choisie
[ ] visuels autorisés identifiés
[ ] informations privées exclues
```

## Matériel

- ordinateur candidat ;
- éditeur déjà disponible ;
- navigateur moderne ;
- dossier personnel clairement identifié ;
- contenus et visuels autorisés ;
- pack de prompts ;
- mini-site de démonstration de la séance 17.

## Message d’ouverture

```text
Aujourd’hui, nous ne cherchons pas à produire un site parfait.
Nous produisons une première version simple, lisible et contrôlable.

Chaque fichier doit avoir un rôle.
Chaque modification doit être comprise.
Chaque test doit être réellement exécuté.
```

## Déroulé — 120 minutes

| Phase | Durée | Résultat |
|---|---:|---|
| Accueil et contrôle des prérequis | 10 min | candidats prêts |
| Cadrage avec 18-A | 15 min | structure confirmée |
| Arborescence et HTML avec 18-B | 20 min | index.html |
| CSS responsive avec 18-C | 20 min | styles.css |
| Interaction avec 18-D | 15 min | app.js |
| Audit et corrections avec 18-E | 20 min | anomalies traitées |
| README et preuve avec 18-F | 15 min | documentation présente |
| Restitution | 5 min | résultat expliqué |

Pour une séance de 90 minutes, conserver tous les contrôles essentiels et terminer la documentation en travail accompagné.

## Démonstration recommandée

1. montrer le mini-site de la séance 17 ;
2. montrer l’arborescence ;
3. modifier oralement un contenu sans toucher au code ;
4. expliquer l’ordre 18-A à 18-F ;
5. rappeler que le prompt ne remplace pas le contrôle ;
6. montrer comment lire une erreur de console ;
7. rappeler l’arrêt avant publication.

## Rôle du formateur

- contrôler le cadrage avant le code ;
- limiter la complexité ;
- vérifier les contenus métier ;
- faire verbaliser le candidat ;
- autoriser seulement les corrections nécessaires ;
- distinguer aide technique et validation ;
- contrôler la preuve finale.

## Erreurs fréquentes

| Erreur | Intervention |
|---|---|
| le candidat demande tout le site en une fois | revenir aux prompts séquentiels |
| contenu métier inventé | arrêter et corriger les inputs |
| fichiers écrasés | restaurer la sauvegarde et reprendre |
| mise en page trop complexe | revenir à quatre à six sections |
| interaction trop ambitieuse | choisir afficher/masquer ou FAQ |
| erreur console ignorée | lire le message et identifier le fichier |
| confusion local/public | rappeler qu’aucun déploiement n’est autorisé |

## Critère de sortie

Le candidat peut recevoir `PRÊT POUR VALIDATION HUMAINE` lorsque le dossier est complet, les tests essentiels sont documentés et le candidat sait expliquer le rôle des trois fichiers principaux.

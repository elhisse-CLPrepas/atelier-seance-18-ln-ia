# Produire le mini-site dans VS Code

1. Dans Atelier, saisir son projet ou charger une démonstration puis adapter tous les champs. Relire les informations et les limites.
2. Exporter le contenu dans 04-WEB/contenu-page-projet.md et le prompt dans 02-PROMPTS/prompt-maitre-mini-site-S18.md. Exporter aussi le carnet JSON pour reprendre les saisies.
3. Ouvrir un dossier de production dans VS Code. Joindre ou copier les fichiers source, logo et visuels réellement disponibles. Un chemin local cité ne transmet pas un fichier à un agent distant.
4. Ouvrir Codex, GPT ou Claude Code dans son environnement habituel. Fournir le prompt exporté et les pièces nécessaires. Demander l’exécution et la création des fichiers, puis du ZIP, dans un sous-dossier dédié.
5. Récupérer le dossier source et l’archive. Si l’agent ne peut pas compresser, utiliser la commande qu’il fournit et vérifier le fichier créé.
6. Extraire le ZIP dans un autre emplacement. Ouvrir index.html, tester l’action principale, les liens, les interactions, le clavier et un écran étroit. Vérifier le contenu de la fiche cible.
7. Consigner les essais réellement faits et les essais manquants dans la preuve S18. Garder le prompt et l’archive comme pièces de reprise S19. La revue du pilote reste nécessaire.

Le site prépare un prompt ; il ne lance pas un agent et ne prétend pas que le pack demandé est déjà produit. Les modèles d’exemple ne constituent pas vos observations personnelles.

Les neuf affiches et la copie consultable du dossier Challenge sont accessibles dans Présentation et Ressources. Le dossier original mon-dossier-challenge-Module05 reste la copie de travail ; l’atelier fournit un instantané de diffusion sans métadonnées Git.
